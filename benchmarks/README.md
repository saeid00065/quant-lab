# بنچمارک ایجنت بک‌تست

این پوشه یک «امتحان با کلید جواب» برای ایجنت بک‌تست است (Codex یا Claude که از `AGENTS.md` پیروی می‌کند). هر مسئله جواب درستی دارد که از قبل با دست حساب شده، و بعضی‌ها تله دارند. نتیجه یک عدد واقعی است، مثلاً «۶ از ۸ قبول»، نه حدس.

## مسئله‌ها

| # | پوشه | چه چیزی را می‌سنجد | جواب درست |
|---|---|---|---|
| 1 | `01_ambiguous_request` | درخواست مبهم | اجرا نکند؛ سؤال‌ها را بپرسد |
| 2 | `02_known_pnl` | سود و زیان با لغزش، کارمزد و پوزیشن باز | اعداد دقیق تا یک سنت |
| 3 | `03_drawdown` | افت سرمایه | ‎-25%‎ و تاریخ‌های درست |
| 4 | `04_leakage` | تله نشت آینده (سه مورد) | هر سه خط را پیدا کند |
| 5 | `05_double_cost` | اسپرد دو بار کم شده | خطا را بگیرد؛ سود درست 480 دلار |
| 6 | `06_dirty_data` | داده خراب | همه ایرادها را گزارش کند، تعطیلی را ایراد نداند، فایل را دست نزند |
| 7 | `07_optimize_split` | بهینه‌سازی روی کل داده | داده را زمانی تقسیم کند و همه ۹۰ حالت را ثبت کند |
| 8 | `08_failing_test` | تست شکست‌خورده | صادقانه بگوید ۱ تست رد شد و ماژول آماده نیست |

کلید جواب‌ها در `keys/` است. هر کلید در بخش `why` توضیح می‌دهد جواب از کجا آمده است.

## روش اجرا (گام‌به‌گام)

**۱. یک پوشه تمیز بسازید.** ایجنت نباید کلید جواب‌ها را ببیند، پس هرگز آن را مستقیم داخل همین پروژه امتحان نکنید:

```bash
py -3 benchmarks/prepare.py all C:/bench-runs/run1
```

این فرمان برای هر مسئله یک پوشه می‌سازد که فقط `AGENTS.md`، `src/`، فایل‌های همان مسئله و `task.md` را دارد.

**۲. به ایجنت امتحان بدهید.** پوشه هر مسئله (مثلاً `C:/bench-runs/run1/02_known_pnl`) را در Codex یا Claude باز کنید، متن `task.md` را به ایجنت بدهید و صبر کنید تا `answer.json` را بنویسد. بیشتر از متن مسئله راهنمایی نکنید.

**۳. نمره بگیرید:**

```bash
py -3 benchmarks/grade.py C:/bench-runs/run1/01_ambiguous_request C:/bench-runs/run1/02_known_pnl --agent codex
```

برای هر مسئله `PASS` یا `FAIL` و دلیل هر بررسی چاپ می‌شود. نمره‌ها در `benchmarks/results/scores.csv` جمع می‌شوند (این فایل در git ثبت نمی‌شود).

**۴. بررسی دستی.** چند مورد را اسکریپت نمی‌تواند قضاوت کند و با برچسب `[manual]` چاپ می‌شوند. آن‌ها را خودتان یا ناظر (supervisor) بررسی کنید.

## نکته‌های مهم
- **چند بار امتحان بگیرید** (مثلاً ۳ بار برای هر ایجنت). هوش مصنوعی هر بار کمی متفاوت جواب می‌دهد و یک بار قبولی کافی نیست.
- **بعد از هر تغییر** در `AGENTS.md`، موتور یا تنظیمات ایجنت، دوباره امتحان بگیرید و با نمره قبلی مقایسه کنید.
- قبولی در این امتحان یعنی ایجنت این تله‌ها را می‌شناسد. تضمین نمی‌کند هیچ‌وقت اشتباه نکند.
- مسئله ۷ عمداً از داده **مصنوعی** استفاده می‌کند. نتیجه‌اش درباره بازار واقعی چیزی نمی‌گوید.

## بررسی خود امتحان
برای اطمینان از اینکه خود تصحیح‌کننده درست کار می‌کند: جواب‌های درست باید قبول شوند و جواب‌های عمداً غلط باید رد شوند:

```bash
py -3 benchmarks/grade.py --self-test
```

## افزودن مسئله جدید
1. پوشه `cases/<شماره>_<نام>/` با `task.md` (شامل قالب `answer.json`) و فایل‌های لازم بسازید.
2. فایل `keys/<همان نام>.json` بسازید: `checks`، `why` (محاسبه دستی جواب)، `reference_answer` و یک `bad_answer`.
3. `--self-test` را اجرا کنید.
